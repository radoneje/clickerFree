# Защита от злоупотреблений

## Принципы

Защита входит в первую версию. Публичный UUID, знание ссылки на устройство или клиентская проверка версии не заменяют серверную авторизацию. Каждая операция проверяет пользователя, роль, устройство и действующее разрешение. Команды ограничены переключением слайдов: исполнение произвольных команд, чтение файлов и удалённая оболочка не предусмотрены.

Настройки ниже — стартовые значения для проверки под нагрузкой. Они хранятся в конфигурации, измеряются и корректируются по наблюдениям. Ограничения IP дополняют ограничения аккаунта и устройства: участники мероприятия могут использовать один внешний IP.

## Повторные запуски и подключения

- На компьютере работает один экземпляр воркера на пользовательскую сессию. Использовать системную блокировку/mutex; второй запуск показывает уже работающий экземпляр и завершает запуск.
- Сервер допускает одно активное соединение на устройство. Повторный запуск не создаёт профиль и не вытесняет бесконечно действующее соединение.
- Законное переподключение атомарно получает новый номер поколения соединения; старое соединение теряет право выполнять команды. При попытках параллельного подключения новых экземпляров применяется задержка и предлагается явное восстановление доступа через кабинет.
- До 10 привязанных устройств на аккаунт, до 5 подключённых пультов на устройство и один управляющий сеанс. Превышение показывает локализованное объяснение.
- Отзыв устройства, сессии или приглашения действует сразу на HTTP и Socket.IO. После перезапуска сервера открытые пульты проходят проверку заново.

## Ограничения частоты

| Действие | Начальный предел | Реакция |
|---|---|---|
| Общие API-запросы | 120/мин на аккаунт; IP-порог 600/мин | HTTP 429, `Retry-After` |
| Начало OAuth-входа | 10/10 мин на браузер; IP-порог 100/10 мин | Задержка и временное ограничение |
| Создание кода сопряжения | 5/час на установку; IP-порог 100/час | Отказ до следующего окна |
| Ввод кода сопряжения | 5/10 мин на аккаунт; 10 попыток на код | Временное ограничение; исчерпанный код аннулируется |
| Создание приглашений | 20/час на аккаунт, 10 одновременно действующих на устройство | Отказ с объяснением |
| Обмен токена приглашения | IP-порог 100/15 мин | HTTP 429, без создания сессии |
| Запросы ссылки скачивания | 10/10 мин на браузер; IP-порог 300/10 мин | HTTP 429, без создания события скачивания |
| Команды | 5/с на управляющий сеанс и устройство, всплеск до 10 | Излишние команды отбрасываются |
| Повторные подключения | 10/мин на устройство; IP-порог 300/мин | Увеличение задержки |

Критичные счётчики HTTP хранятся на сервере и не сбрасываются обычным перезапуском. Ограничения для неавторизованного трафика действуют также в Nginx, до обращения к базе. Значения не суммируются слепо: отдельные маршруты имеют собственные лимиты. Ошибка хранилища лимитов не должна открывать неограниченный вход — критичные операции временно недоступны. Callback OAuth учитывается отдельно, чтобы завершение законного входа не блокировалось лимитом его начала.

## Пароли, коды и приглашения

Локальных паролей аккаунтов в первой версии нет: вход только через VK/Яндекс. Не хранить копии паролей провайдеров.

Ссылка спикера содержит криптографически случайный токен в формате длинного GUID: два UUIDv4 без дефисов (64 hex-символа, 244 бита энтропии, не менее требуемых 128 бит); в базе хранится хеш. Токен обменивается на короткую ограниченную сессию и удаляется из адресной строки. Открытие ссылки само по себе не расходует приглашение: ссылки могут проверять предпросмотры мессенджеров. Явный отзыв завершает все выданные по приглашению сессии.

Пароль приглашения в первой версии не используется (решение владельца 2026-11-16): доступ защищает энтропия токена, срок действия, лимиты обмена и отзыв. Подбор токена практически невозможен при 244 битах энтропии; лимиты обмена ограничивают перебор и злоупотребления.

Код сопряжения — 8 случайных символов из алфавита без неоднозначных знаков, действует 5 минут, используется один раз. Подтверждение привязки требует авторизованного аккаунта. Воркера снабдить отдельным секретом для проверки результата: одного короткого кода недостаточно для получения ключа устройства.

Учётные данные устройства состоят из случайного секрета не менее 256 бит; сервер хранит хеш. Локальное хранение — системное хранилище секретов; идентификатор и название могут оставаться в конфигурационном файле. Предусмотреть отзыв и ротацию ключа.

## Скачивания и достоверность статистики

Разделять переходы, первые обращения установок и привязки; исключать отклонённые запросы, известные проверки доступности и повторные `eventId`. Клиентский сигнал первого запуска не считать достоверным доказательством уникального человека. Подозрительные события помечать и исключать из основных метрик, сохраняя отдельный агрегат.

Перенаправление на публичный GitHub Release не защищает сам файл от скачивания в обход сайта. Лимиты сервиса защищают его endpoint и статистику. Если потребуется контролировать весь трафик загрузок, использовать отдельное хранилище с временными ссылками и журналами выдачи. Нельзя обещать точный подсчёт всех скачиваний публичных файлов.

## Веб, сеть и доступ администратора

Только HTTPS/WSS. CORS и Origin ограничены доменом сервиса. Не доверять присланному пользователем IP: Fastify принимает forwarded-заголовки только от локального Nginx. API и PostgreSQL недоступны напрямую из интернета.

Проверять схемы сообщений, длины строк и размер тела запроса; стартовый предел HTTP — 64 КБ, Socket.IO — 8 КБ. Использовать параметризованные запросы, CSP, запрет встраивания пульта в чужие сайты и `Referrer-Policy: no-referrer` на страницах приглашений. Не подключать стороннюю аналитику на страницы с токенами.

Не записывать в access-логи секретные query-параметры, OAuth-коды, cookies и ключи. Секреты не передавать в логи ошибок. Ошибки входа не раскрывают существование аккаунта. Настройка Nginx должна учитывать очистку URL в журналах.

Доступ администратора назначается явно, не по непроверенному email и не через публичную регистрацию. Для админки обязательны дополнительный фактор (TOTP или WebAuthn), повторное подтверждение критичных действий и журнал изменений ролей, блокировок и релизов.

## Эксплуатация и проверка

Оповещения: рост 429/ошибок авторизации, частые переподключения, необычный объём загрузок, заполнение диска, недоступность базы. Сначала ограничивать конкретный источник; CAPTCHA подключать при подозрительной активности, а не перед каждым переключением.

Перед запуском проверить: доступ к чужому UUID, истёкшие и отозванные ссылки, перебор кода привязки, подбор токена приглашения, повторный запуск воркера, повтор команды, подмену Origin/IP, создание устройств сверх лимита, массовые загрузки и превышение частоты команд. Ошибка аналитики не должна мешать управлению. Резервные копии проверяются восстановлением.
